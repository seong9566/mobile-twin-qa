# QA 맥 앱 설계 (2026-10-26)

## 1. 왜 만드는가

지금은 등록(qa-init) → 계획(qa-plan) → 실행(qa-run) → 보고를 모두 Claude Code 채팅으로 한다. 사용자는 이것을 **macOS 앱 하나**에서 하려고 한다: 앱 소스 폴더를 고르면 QA 목록을 만들고, 사용자가 목록을 고친 뒤 테스트를 돌리고, 최종 결과를 보여 준다. 결과에서 실패 건을 골라 **앱 코드를 고치는 LLM에게 넘길 .md 파일**을 만든다.

성공: 채팅보다 편하고, 테스트가 멈추면 바로 알고, 비용이 모르게 새지 않고, 결과를 근거(영상·checks)로 믿을 수 있다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 프로젝트 폴더 선택 → 등록 → 시나리오 목록 → 목록 확인·수정 → 실행 승인 → 실행 진행 표시 → 결과 화면 → 수정 요청 .md
- Android 실기기 + Artemis

**비목표 (이번에 하지 않음)**
- iOS(mobile-mcp). 단, 러너를 바꿔 끼울 수 있게 구조만 연다.
- 다른 맥·팀원 배포, 코드 서명·공증. 사용자 한 명이 이 맥에서 Xcode로 빌드해 쓴다.
- 앱 원본 repo 수정. 이 앱은 원본을 읽기만 한다(AGENTS.md "원본 repo").

**반목표 (이렇게 되면 실패)** — 사용자가 고른 네 가지
- 테스트가 멈추거나 Wi-Fi가 끊겨도 앱이 모르고 하염없이 기다린다.
- 채팅보다 클릭이 많고 느리다.
- 모르는 사이 LLM 호출이 계속 돈다.
- 도구 오판을 앱 결함처럼 보여 주거나, 판정에 근거(영상·checks)가 없다.

## 3. 제약

- 회사 프로젝트 데이터(계획·결과·녹화)는 이 맥 밖으로 내보내지 않는다. 앱은 로컬 파일만 읽고 쓴다(LLM 제공자로 가는 스크린샷은 승인 창의 승인을 따른다).
- 비밀값은 `.env`에만 있다. 앱은 `.env` 값을 화면·로그·`results.json`·.md에 보여 주지 않고, Claude Code 프롬프트에도 넣지 않는다(4.6).
- Artemis 쓰기 호출(`POST /api/run`·`/api/stop`)은 앱만 한다. 승인 창에서 사용자가 승인한 실행 안에서만, 그리고 아래 4.5의 자동 중지·사용자의 "중지"에서만 부른다. 상태 확인은 GET.
- Artemis 포트는 8100. 8000은 건드리지 않는다.
- 판정·기록·지식 규칙의 정본은 지금처럼 스킬(`.claude/skills/qa-*/SKILL.md`)과 `AGENTS.md`다. 앱이 맡는 실행 루프(4.5)는 스킬에 "앱이 한다"고 적어 정본이 어디인지 남긴다.

## 4. 사용자가 정한 것

### 4.1 일하는 LLM은 이 맥의 Claude Code
앱은 `claude -p`(헤드리스, `--output-format stream-json`)를 mobile-twin-qa 메인 작업 트리에서 실행해 기존 qa-init·qa-plan·qa-run 스킬을 쓴다. 앱은 화면·승인 창·진행 표시·결과 보기와 Artemis 실행 루프(4.5)를 맡는다.

### 4.2 흐름과 화면

1. **프로젝트 고르기** — 앱 소스 폴더 선택. mobile-twin-qa에 등록돼 있지 않으면(`project.local.yaml`의 `source_path`로 대조) 등록부터 한다. 왼쪽 사이드바: 프로젝트 → 계획 → 실행 날짜.
2. **QA 목록 만들기** — qa-plan 실행. 끝나면 시나리오 표.
3. **목록 확인·수정** (사용자가 고친 뒤 시작)
   - 칸: ID · 제목 · 등급(A 자동/B 반자동/C 수동) · 플랫폼
   - 체크로 빼기, 줄을 열어 goal·통과 조건 수정, 순서 바꾸기(앞 결과가 뒤 사전 조건)
   - C 등급은 처음부터 빠짐(목록만)
   - goal에 실제 발신·삭제·결제 같은 동작이 보이는데 "누르지 마"가 없으면 경고
4. **실행 승인 창** — 지금 채팅에서 받던 승인을 한 창에서: 기기(`adb devices -l`), 서버(`project.yaml`의 `environments`), 실행할 시나리오와 B 등급의 사람이 할 동작, 계정(4.6), 회사 프로젝트면 스크린샷 LLM 전송 승인, 비용 상한.
5. **진행 화면** — 시나리오별 대기·진행 중·통과·실패·보류, 현재 시나리오의 경과 시간·LLM 호출 수·누적 토큰. 접는 로그: Claude Code 출력, Artemis `stdout.log`. B 등급 시나리오가 시작되면 macOS 알림으로 사람이 할 동작을 알린다. "중지" 버튼.
6. **결과 화면**
   - 맨 위: 통과 n · 실패 n · 보류 n · 미실행 n · 전체 n, 비용 한 줄(LLM 호출 수·토큰 합계)
   - 실패·보류 카드: 의도한 동작 → 실제 동작, 원인 구분(앱 결함·도구 오판·환경), 영상 바로 재생, checks 요약, 수정할 점 메모 칸, .md 포함 체크박스. 원인 구분은 사용자가 바꿀 수 있다.
   - 보류·미실행은 사유와 함께
   - 메모·원인 변경은 그 실행 폴더에 별도 파일로 저장해 다시 열어도 남는다.
7. **수정 요청 .md 만들기** — 저장 위치 선택 창 + 클립보드 복사.

### 4.3 수정 요청 .md (받는 쪽: 앱 코드를 고치는 LLM)
- 머리말: 앱 이름, 소스 브랜치·커밋 SHA·앱 버전, 기기, 서버
- 체크한 실패마다: ID·제목, 테스트 순서(goal), 통과 조건과 근거 `파일:줄`, 기대 → 실제, 원인 구분, 녹화·스크린샷 경로, 사용자 메모
- 맺음말: 코드에서 원인을 찾아 수정안을 내라는 요청 한 줄. 도구 오판으로 표시한 항목은 고치지 말라는 안내(포함했을 때).
- 비밀번호·토큰 없음. 환경 변수 이름만.

### 4.4 기타 결정
- Android만(Artemis). iOS는 나중.
- 나만, 이 맥에서. 서명·배포 없음.
- 진행 표시는 상태 + 접는 로그.

### 4.5 실행 단계의 역할 나눔
- **앱이 Artemis를 직접 부른다.** 승인 창 승인이 쓰기 승인이다(전역 hook 예외 설정은 하지 않는다). 앱이 하는 일: 시나리오를 하나씩 `POST /api/run`(계획의 실행 옵션 + `device_serial`), `GET /api/sessions/{id}`로 상태 보기, 멈춤 감시, 중지, 끝난 시나리오의 녹화(`video_url`)·`checks`·`usage`를 `artifacts/<ID>/`에 받기, 앞 시나리오가 실패하면 그것을 사전 조건으로 둔 뒤 시나리오는 보내지 않고 보류.
- **Claude Code가 하는 일**: 실행 전 준비(빌드·설치·Android 로그인, qa-run의 기존 절차), 실행 뒤 판정(녹화·스크린샷 확인)·`summary.md`·지식 반영.
- **비용 상한**: 승인 창에서 Artemis 기준(LLM 호출 수 또는 입력 토큰)으로 정한다. 실행 중 `usage` 합계가 넘으면 **자동 중지** — 지금 시나리오를 멈추고 남은 건은 미실행(사유 "비용 상한")으로 두고 판정 단계로 간다. Claude Code 단계에는 `--max-budget-usd`도 따로 건다.
- **멈춤 감지**(`tools/artemis.md` "멈춤 감시" 기준: 로그 5분 정지, 마지막 단계 요약 뒤 도구 없이 멈춘 LLM 12회): **경고 후 사람이 결정** — 화면 경고와 macOS 알림, "이 시나리오 중지 → 보류" 버튼. 앱이 스스로 멈추지 않는다.
- **Wi-Fi 끊김**: 앱이 `adb -s <serial> shell cmd wifi status`로 확인해 경고한다. 사용자가 고친 뒤 "다시 돌리기"를 누르면 첫 시도를 `artifacts/<ID>/try1/`로 옮기고 한 번 다시 돈다(qa-run 규칙).

### 4.6 로그인 정보 입력 란
- 대상: 테스트할 앱의 계정만(프로젝트 `.env`). Artemis 자체 키(`$ARTEMIS_HOME/.env`)는 앱에서 다루지 않는다.
- 실행 승인 창의 "계정" 칸: 이번에 고른 시나리오에 필요한 키 이름(계획 "준비"의 "계정 (`.env` 키 이름)")마다 ✓ 있음 / ⚠ 없음. 없는 키가 있으면 "시작"이 꺼진다. 프로젝트 설정 화면에서도 언제든 고친다.
- 입력은 가려지는 칸(SecureField). 저장된 값은 다시 보여 주지 않고 "바꾸기"만 있다.
- 앱이 `company|personal/<project>/.env`에 직접 쓴다(git 제외 파일). 형식은 `android-login.sh`가 읽는 대로 한 줄에 `KEY=value`이고, 다른 줄과 주석은 그대로 둔 채 해당 키 줄만 바꾸거나 더한다. 값은 LLM을 거치지 않는다 — Claude Code는 지금처럼 `tools/android-login.sh`로 `.env`를 읽어 로그인한다.

## 5. 내가 정한 것 (Claude의 판단 — 사용자가 뒤집을 수 있음)

- **SwiftUI macOS 앱**, 영상은 AVKit. 이 맥: Xcode 27.0, Swift 6.4, macOS 27.0.1.
- **위치**: mobile-twin-qa 저장소의 새 최상위 폴더 `app/`. AGENTS.md "폴더 구조"와 "작업 위치와 커밋" 표에 `app/`을 추가한다. 앱 소스는 워크트리 PR로 머지한다. 빌드 산출물은 git 제외.
- **단계마다 Claude Code를 따로 실행**: 등록, 계획, 실행 준비, 판정. 목록 확인은 계획 뒤에, Artemis 루프는 준비와 판정 사이에 앱이 한다.
- **헤드리스용 스킬 보완**: 각 스킬에 "앱에서 실행될 때" 절을 더한다.
  - 사용자에게 묻는 대신 앱이 넘긴 답(범위, 승인 내용, 계획이 낡았을 때 계속 여부)을 쓴다. 넘기지 않은 결정이 필요하면 멈추고 이유를 남긴다.
  - qa-run은 "준비"와 "판정·기록" 두 부분으로 불리고, 실행 루프는 앱이 한다고 적는다.
  - 커밋은 하지 않는다. 개인 프로젝트면 앱이 결과 화면에 "커밋" 버튼을 보여 준다.
- **목록 수정 저장**: goal·통과 조건을 고쳤을 때, 아직 실행한 적 없는 계획이면 그 파일에, 실행 기록이 있는 계획이면 새 계획 파일로 저장한다(AGENTS.md 파일명 규칙). qa-plan·qa-run의 "기존 계획 파일은 고치지 않는다"에 "실행 전, 앱에서 사용자가 고친 경우"를 예외로 더한다. 뺀 시나리오와 순서는 계획 파일에 쓰지 않고 실행 목록으로만 쓴다.
- **미실행 집계**: 이번에 고른 시나리오 기준.
- **결과 파일**: 앱에서 실행하면 qa-run이 `summary.md`와 함께 `results.json`(시나리오별 결과·원인 구분·기대·실제·근거 경로)을 쓴다. 판정 값은 앱 결함·도구 오판·환경·— 넷으로 고정한다. 옛 실행 기록은 `summary.md` 표와 "실패·보류 상세"를 느슨하게 읽어 보여 준다(못 읽은 칸은 비워 둔다).
- **다시 돌리기**: 같은 실행 폴더에서, 첫 시도는 `try1/`로.
- **B 등급**: 앱은 알림만 보내고, 사람이 동작했는지는 Artemis가 화면에서 알아본다.
- **메모 파일**: 실행 폴더의 `review.json`. 회사 프로젝트는 git에 올라가지 않는다(`company/*` 제외).
- **.md 기본 위치**: 실행 폴더의 `fix-request.md`(저장 창에서 바꿀 수 있음).
